# AI 味体检 · 中文小说 AI 痕迹辅助判断

**在线试用 → https://qscnet.github.io/Qsc-AI/**

> 纯前端。稿子在你自己的浏览器里跑，一个字都不上传。
> 要开完整服务（REST API、Key 鉴权、限流、配额）：见下方「三、怎么跑」。

---

面向**中文小说**的 AI 生成痕迹检测工具。纯前端可离线跑，也可一条命令起成 API 服务卖给客户。

```
双击 index.html        → 立刻能用，零安装、零联网、稿件不出本机
node server.js        → 网页 + REST API 同端口，带 Key 鉴权、限流、配额
```

## 一、先说清楚它是什么

它**不是**模型分类器，也**不是**「AI 生成鉴定书」。

它做的事情是：把一段中文小说拆成 **55 个可量化特征**（句长变异、叠词副词密度、眼神表情模板、「不是…而是」句式、语义重复搭配、句式杂糅、话题断裂、标点种类数、相邻句相似度、模糊限定词、视觉垄断度……），
逐项对比「人类写作参考值」和「AI 生成参考值」，算出偏离度，加权成 **0–100 的 AI 味指数**，并把每条偏离对应的**原文段落**摆出来。

| | 朱雀类产品 | 玄武 |
|---|---|---|
| 判定方式 | 训练出来的分类器，黑箱 | 统计特征 + 明码阈值 |
| 输出 | 一个百分比 | 指数 + 10 维拆解 + 55 项明细 + **可疑段落原文** + 改写建议 |
| 粒度 | 段落 | **段落为主**（可直接发作者），句级细看另附 |
| 能否解释「为什么」 | 不能 | 能，每一条都能指到原文那一段的那几个词 |
| 部署 | 云端，稿件要上传 | 本地私有化，稿件留在自己机器 |
| 成本 | 按次/订阅 | 零成本（大模型裁判可选，按需付费） |
| 上限 | 更高 | 略低，但足够做筛选初筛和改稿自检 |

**对外话术请务必只讲「疑似度 + 证据」，不要讲「判定为 AI 生成」。** 见第十一节。

## 二、30 秒上手

### 方式 A：纯网页（不需要 Node）

直接双击 `index.html`，浏览器打开就能用。所有计算在浏览器里跑，不联网、不上传。

功能：单段检测、整本拆章、批量、双文本对照、解释面板。

> 这台的浏览器需要支持 `TextDecoder`、`Canvas`（Chrome / Edge / Firefox / Safari 近代版本都行）。
> 打开 txt 时会出现乱码的话，是把 ANSI/GBK 编码误当 UTF-8 了 —— 页面已内置自动回退到 GBK，正常不会出问题。

### 方式 B：带 API（推荐给要做生意的场景）

```bash
cd 玄武AI检测
node server.js
```

第一次启动会自动生成 `keys.json` 并在控制台打印一把 Key：

```
  玄武 · 小说 AI 味检测  引擎 v1.0.0，55 项特征
  ----------------------------------------------------
  网页      http://127.0.0.1:8787/
  健康检查  http://127.0.0.1:8787/api/v1/health
  Key 数量  1（配置文件 keys.json）
  大模型裁判 未配置（设 JUDGE_API_KEY 可开启）
```

然后用 `http://127.0.0.1:8787/` 打开页面 —— 网页和 API 同一个端口，右边「API」页签可以对着真实服务试调。

只要 Node 14+，**没有任何 npm 依赖**，`node_modules` 是空的，拷到内网机器上照样跑。

## 四、检测原理

### 打分链路

```
文本 → 预处理（切段/切句/标点/对话/词表扫描）
     → 特征层（55 项，每项算实测值）
     → 归一层（线性映射到 0–1 的偏离度，锚点明码写在代码里）
     → 聚合层（10 维加权 → AI 味指数 0-100 + 置信度）
     → 段落层（段内套路强度 z 分 + 句级均分 → 每段一个分 + 命中原文）
     → 定位层（句级滑动窗口 → 热力图，给编辑细看）
     → 建议层（每条命中配一条可执行的改法）
```

没有神经网络，没有任何隐藏权重。**全部可以在 `assets/engine.js` 里读到改到。**

### 八个维度

| 维度 | 权重 | 看什么 | 典型发现 |
|---|---|---|---|
| 句式节奏 | 1.15 | 句长变异系数、短句率、节拍器连击、单句成段率 | 「连续 7 句长度都在 22±3 字」 |
| 用词习惯 | 1.10 | 叠词副词、四字成语、抽象大词、具体物、数字量词 | 「叠词副词 8.4/千字，人类常见 <1.8」 |
| 套路句式 | 1.30 | 不是…而是、排比、仿佛…一般、眼底闪过、嘴角勾起一抹 | 「眼神表情模板 6 处」 |
| 语病杂糅 | 1.30 | 语义重复、句式杂糅、主语残缺、关联词残缺、一逗到底、长句无停顿 | 「大约…左右」×3、「虽然…」后面没有「但是」 |
| 逻辑松散 | 1.00 | 话题断裂、车轱辘话、前后矛盾 | 「相邻 6 句内容词零重叠且无转场」 |
| 标点口语 | 1.00 | 标点种类数、破折号、感叹问号、语气词、网络用语 | 「全文只用了 3 种标点」 |
| 重复自噬 | 0.95 | 6 字串复用、句首雷同、相邻句相似度 | 「相邻两句字符重合度 0.31」 |
| 意象感官 | 0.90 | 视觉垄断度、对话占比、对话句长、具体动作 | 「视觉词占全部感官词 89%」 |
| 空转密度 | 1.15 | 似乎/仿佛/某种/下意识、空转句、升华式收尾 | 「段末总结句占 34%」 |
| 可预测性 | 0.55 | 字符级条件熵（困惑度廉价代理，实验性） | 「文字过于可预测，像按模板生成」 |

### 输出粒度：段落为主

和朱雀一致，**对外的结论是「段」，不是「词」**：

```json
"suspiciousParagraphs": [
  {
    "index": 2, "score": 84, "verdict": "high", "chars": 236, "sentences": 5,
    "text": "夜色如水，月光透过窗棂洒落在她的脸上……",
    "flags": [ {"id":"redup","name":"叠词副词","count":3} ],
    "hits":  [ {"id":"syn_gaze","name":"眼神表情模板","count":2,"samples":["嘴角勾起一抹"]} ]
  }
]
```

网页上会渲染成一张张段落卡：**第几段 · 多少分 · 属于哪个档 · 原文 · 命中依据**，点「复制段落报告」就能得到一段可以直接发给作者的纯文本：

```
【玄武 · 小说 AI 味检测报告】
检测时间：2025-01-01 12:00:00
全文 3,240 字 / 128 句 / 32 段
判定：疑似 AI　AI 味指数：62　置信度：较高（±6）

结论：全文 32 段中有 8 段越过「疑似」线，其中 3 段达到「高度怀疑」，
      合计约 820 字（占 25%）。

■ 高度怀疑 AI（3 段）
  第 2 段｜84 分
　「夜色如水，月光透过窗棂洒落在她的脸上……」
　依据：叠词副词×3、眼神表情模板×2

■ 疑似 AI（5 段）
  第 7 段｜51 分
　「她轻轻叹了口气，手指无意识地抚过……」
　依据：模糊限定×2

主要偏差维度：套路句式 91　空转密度 78　句式节奏 66

说明：本报告为基于统计特征的疑似度估计，不构成对文本来源的最终认定；
每条结论都能定位到原文对应段落，可供作者申诉与人工复核。
```

逐句热力图仍然保留，但收在「细节」折叠里——那是给编辑改稿用的，不是给客户看的。

### 网页上的染色

检测完，**左边「待检文本」会被原地替换成标注视图**。两种呈现，不制造视觉噪音：

**全部通过时**——整块一个颜色，不分段：

```
┌ 全部通过 · 人写 ────────────────────────┐
│ 楼道里的声控灯又坏了。我摸黑上了四楼……   │
│ "操。"我把外卖扔桌上，"又他妈凉了。"     │
└──────────────────────────────────────┘
```

**有可疑段落时**——只把有问题的段单独标出来，其余保持素文：

```
楼道里的声控灯又坏了。我摸黑上了四楼……      ← 素文，不上色
"操。"我把外卖扔桌上，"又他妈凉了。"        ← 素文

[高度怀疑 74] 夜色如水，月光透过窗棂……    ← 单独标出

我没接话。豆浆烫手，我换了个手拿……          ← 素文
```

颜色和标签：

| 颜色 | 结论 | 段落分 |
|---|---|---|
| 🟩 绿 | 人写 | < 40 |
| 🟨 黄 | 疑似 AI | 40–69 |
| 🟥 红 | 高度怀疑 AI | ≥ 70 |

标出来的段落开头带一枚小标签（`疑似 51` / `高度怀疑 74`），点它会跳到右侧对应的卡片并闪一下；**鼠标悬停**还会浮出这一段的内部构成。底部有「编辑 / 标注结果」切换，随时回去改文本；一改动，旧标注自动作废。

**鼠标悬停在标出来的段落上**，会浮出一张小卡片，告诉你这一段的构成：

```
■ 疑似 AI 占比：62.5%
该片段命中了部分模型书写特征，也可能是人机混写或人工润色后的结果。
```

悬停卡片里的百分比是**这一段的内部构成**（按句长加权），不是全文的。段级结论取占比最大的那一档。

> 如果粘贴的是一大坨没有换行的文本，段落级染色会退化成一整片同色。这种情况页面会自动按句子切成 ~220 字的块来上色（标签显示为 `2·1`、`2·2`），保证你能看出落差在哪。
>
> 三档阈值就是 README 第五节的判定区间，改动 `assets/engine.js` 里的 `BANDS` 即可（比如想让「通过」更宽松，把 `mixed` 的 `min` 从 40 调到 45）。

### 判定区间：对外只给三档

和朱雀一致，**对客户只讲三档结论**，不抛一堆百分位让人猜：

| AI 味指数 | 结论 | 含义 | 处置建议 |
|---|---|---|---|
| 0–39 | 🟢 **人写** | 未检出成规模的机器书写特征 | 直接通过 |
| 40–69 | 🟡 **疑似 AI** | 命中部分模型书写特征，也可能是人机混写、AI 初稿人工润色 | 人工复核；占全文超 30% 再走下一步 |
| 70–100 | 🔴 **高度怀疑 AI** | 多项模型书写特征同时命中，分布集中在模型一侧 | 要求作者说明创作过程或提供修改记录 |

0–100 的分数只作为内部刻度，用来排序、定位段落；对外的结论永远只有这三句话。改动 `assets/engine.js` 顶部的 `VERDICTS` 即可调整阈值和文案（比如想把「高度怀疑」的门槛放到 75，改那一条的 `min` 就行）。

### 通顺度：和 AI 味分开的第二条线

朱雀会把「读不通的句子」也算进不通过。我们的处理是**两条线分开算、一个结论放行**：

- **AI 味指数**：像不像机器写的
- **通顺度**（0–100）：句子读得顺不顺，由「语病杂糅」占 60% +「逻辑松散」占 40% 折算
  - ≥ 85 通顺　·　65–84 略有瑕疵　·　< 65 明显不通顺

放行规则：**人写 + 通顺** 才算通过。

| AI 味 | 通顺度 | 结果 |
|---|---|---|
| 人写 | 通顺 | ✅ 通过 |
| 人写 | 明显不通顺 | ⚠️ 不通过 —— 文字质量不达标 |
| 疑似 AI / 高度怀疑 AI | 任意 | ❌ 不通过 —— 疑似机器书写 |

这样区分是有意的：一篇「人写的病句流水账」不该被扣上"AI 生成"的帽子（那会冤枉作者、也会被投诉），但它同样不该被放过去。两条线合起来给结论，责任分得清。

### 结果区（和朱雀同款结构）

右边从上到下：

1. **结论横幅**——`人工创作特征显著` / `疑似 AI 特征明显` / `AI 创作特征显著`，右上角「⭳ 下载报告」
2. **免责提示**——灰底一行：「本结果仅为辅助判断，不应作为任何审核或处罚的决策性依据」
3. **三档环形图**——按**段落字数占比**画的三色环，不是单一分数：
   - 🟩 人工特征 88.5%　🟨 疑似 AI 0%　🟥 AI 特征 11.5%（三者相加 100%）
   - 百分比浮在环外，后面跟一个 ⓘ，悬停会解释这一档是什么、怎么算出来的
   - 环心留空（和朱雀一样）。AI 味指数单独做成下面一枚彩色 chip，避免出现「100% 人工特征、环心却写着 23 分」这种看着别扭的组合
4. **👍 👎 ⭳**——👍 表示判断准确，直接按当前结论打标进训练集；👎 表示判断有误，打相反标签；⭳ 生成可打印报告单
5. 再往下才是可疑段落卡片、维度拆解、句级热力图、去 AI 味清单

主按钮上直接带剩余次数：`立即检测（今日剩余 19 次）`。

### 下载报告单（另存为 PDF）

点横幅右上角的「⭳ 下载报告」，会新开一个窗口并自动弹出打印对话框——把「目标打印机」选成 **另存为 PDF**，得到的就是一张分页报告单，结构和朱雀那张一致：

1. 页眉：左边时间，右边报告编号（`玄武AI味检测报告单_20251026235709`）
2. 大标题 + 检测时间 + 判定 + AI 味指数 + 置信度
3. **检测结果**：左边三色图例，右边环形图，百分比浮在环外
4. **AI 分布图**：一条三色堆叠条 + 区间说明（0–39 / 40–69 / 70–100）
5. **片段解析**：把「连续同档的段落」合并成一个片段（和朱雀的片段划分逻辑一致），逐行给：结论、占全文比例、占字符数、AI 味
6. **检测片段详情**：只展开疑似和高度怀疑的片段，附完整原文（全人写的就不重复印一遍了）
7. 页脚免责声明

两个实现细节：

- 环形图用 **SVG 描边**画，不用 CSS `conic-gradient`——浏览器打印默认可能不输出背景色，SVG 一定印得出来；另外全表加了 `print-color-adjust: exact` 兜底。
- 报告是新窗口里 `document.write` 出来的独立 HTML，不依赖主页面，可以直接发给客户。

> 想要 PNG 而不是 PDF 也能加：把报告 HTML 用 canvas 渲染一遍存图片即可。但 PDF 更清楚、也能分页，建议用这个。

### 置信度

按中文字数自动给区间，不是装饰：

| 字数 | 置信度 | 误差 |
|---|---|---|
| < 200 | 极低 | ±35，页面会直接警告「请勿据此判定」 |
| 200–500 | 低 | ±18 |
| 500–1500 | 中 | ±10 |
| 1500–5000 | 较高 | ±6 |
| > 5000 | 高 | ±4 |

**低于 200 字不给结论。** 这是原则问题，别为了好看把它调高。

## 五、API 文档

Base URL 默认 `http://127.0.0.1:8787`。全部 `POST` 接受 `application/json`，返回 UTF-8 JSON。

### 鉴权

```http
X-API-Key: xw_live_xxxxxxxxxxxxxxxx
```
或
```http
Authorization: Bearer xw_live_xxxxxxxxxxxxxxxx
```

- Key 在 `keys.json` 里维护，支持每个客户一把、单独设速率和配额。
- 从本服务打开的网页（同源 Referer）走「本地网页通道」，免 Key、60 次/分钟。要关闭：`ALLOW_LOCAL_UI=0`。
- 完全不要 Key（仅内网调试）：`ALLOW_ANON=1`。

### 端点

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/v1/detect` | 单段检测，返回完整报告 |
| POST | `/api/v1/batch` | 批量检测，一次最多 50 段 |
| POST | `/api/v1/chapters` | 整本拆章，逐章打分 |
| POST | `/api/v1/compare` | 双文本对照 |
| POST | `/api/v1/judge` | 大模型裁判（需服务端配 Key） |
| POST | `/api/v1/feedback` | 打标：`{"label":"ai\|human\|unsure","text":"..."}` |
| GET | `/api/v1/health` | 健康检查（含裁判、校准、样本数） |
| GET | `/api/v1/features` | 55 项特征字典（可解释性凭证） |
| GET | `/api/v1/quota` | 当前配额余量 |
| GET | `/api/v1/stats` | 样本数、准确率、AUC |
| GET | `/api/v1/calibration` | 当前校准参数 |
| GET | `/api/v1/usage` | 当前 Key 的累计用量 |

### `POST /api/v1/detect`

```bash
curl -X POST http://127.0.0.1:8787/api/v1/detect \
  -H "Content-Type: application/json" \
  -H "X-API-Key: $KEY" \
  -d '{"text":"夜色如水，月光透过窗棂洒落在她的脸上……"}'
```

可选参数：


## 六、大模型裁判（可选，默认关闭）

规则引擎的上限在那儿，加一层大模型交叉验证会明显更准。做法是：**规则跑主力，模型出第二意见，两者分歧大就提示人工复核。**

开启方式（任何 OpenAI 兼容接口都行：DeepSeek / 通义 / Moonshot / vLLM 本地模型 / OpenAI）：

```bash
# Windows PowerShell
$env:JUDGE_API_KEY="sk-xxxxxx"
$env:JUDGE_MODEL="deepseek-chat"
node server.js
```

```bash
# Linux / macOS
JUDGE_API_KEY=sk-xxxxxx JUDGE_MODEL=deepseek-chat node server.js
```

| 变量 | 默认 | 说明 |
|---|---|---|
| `JUDGE_BASE_URL` | `https://api.deepseek.com/v1` | OpenAI 兼容 base |
| `JUDGE_API_KEY` | 空（关闭） | 配了才启用 |
| `JUDGE_MODEL` | `deepseek-chat` | 模型名 |
| `JUDGE_TIMEOUT_MS` | `25000` | 超时 |

开启后：
- 网页检测栏的「大模型裁判」勾选框会亮起来，勾上就会在本地结果下面追加一张模型意见卡；
- API 里给 `/detect` 传 `"judge": true`，或直接调 `/judge`。

**Key 只在服务端，浏览器永远拿不到。** 前端不用改一行就能接上。

成本参考：每次约 1500 input + 300 output token，按 deepseek 的价格算，一条一分钱以内。

## 七、调参指南

参数全在 `assets/engine.js`，改完刷新页面就生效（服务端要重启）。

### 1. 改词表

文件开头的 `LEX` 对象就是全部词典：`redup`（叠词）、`hedge`（模糊限定）、`abstract`（抽象大词）、`concrete`（具体物）、`idiom`（成语）、`slang`（口语）……

```js
LEX.redup = ('轻轻 缓缓 淡淡 微微 静静 慢慢 深深 默默 渐渐 悄悄').split(' ');
```

想加你们平台的词，直接往数组里塞，用空格分隔。空格是分隔符，词本身不能含空格。

### 2. 改锚点（推荐先调这个）

每个特征的定义里有两个数：

```js
F({ id: 'lex_redup', dim: 'lexicon', name: '叠词副词密度',
    dir: 'up', h: 1.8, a: 6.0, w: 3, ... })
```

- `h` = 人类参考值，低于它算 0 分（不像 AI）
- `a` = AI 参考值，高于它算满 1 分（很像 AI）
- `dir: 'up'` 越大越像 AI；`'down'` 越小越像 AI
- `w` = 权重

判断方向反了就把 `dir` 改掉；太敏感就把 `h` 往 AI 那边挪（比如 `h: 3.0`），太迟钝就挪回来。

### 3. 改维度权重

顶部 `DIMS` 里的 `weight`。比如你的客户主要是古风文，标点口语一项老是误伤：

```js
{ key: 'punct', name: '标点口语', weight: 0.5, ... }
```

也可以在调用 API 时临时传 `options.dimWeights`，不用改代码。

### 4. 用你自己的语料校准（真正提升准确率的办法）

这一步值得做，而且不难：

1. 收集 **50–100 段你确信是真人写的**（同一个作者的正常章节）、**50–100 段你确信是 AI 写的**；
2. 每段跑一次 `/api/v1/detect`，把 `features` 里的 `value` 和 `norm` 导出来；
3. 对每个特征，取真人组的均值/分位数当新的 `h`，取 AI 组的均值当新的 `a`；
4. 回填 `engine.js`，再跑一遍混合样本，看准确率和误判率。

经验上，**用 100 对语料校准之后，误判率能降一半以上**，这比换更复杂的模型划算得多。

## 九、训练与校准（让系统越用越准）

这是这个工具和「一次性脚本」最大的区别：**它能从你的标注里学。**

### 闭环长什么样

```
用户检测 → 点「这是 AI 写的 / 这是人写的」 → 样本落进 samples.jsonl
        → node calibrate.js 重算 55 项特征的锚点和权重 → calibration.json
        → 服务端 15 秒内自动热加载 → 下一次检测就用新参数
```

### 第一步：标数据

在网页检测结果的底部，有三个按钮：

- **这是 AI 写的** → `label: "ai"`
- **这是人写的** → `label: "human"`
- **说不准** → `label: "unsure"`（入库但不参与训练）

也可以用 API 批量打标（适合你已经有一批确认过的语料）：

```bash
curl -X POST http://127.0.0.1:8787/api/v1/feedback \
  -H "Content-Type: application/json" \
  -H "X-API-Key: $KEY" \
  -d '{"label":"ai","text":"夜色如水，月光透过窗棂……"}'
```

要点：

- **每类至少 8 条**才能训练，**30 条以上**才有明显效果，100 条起才算稳。
- 样本要杂：不同作者、不同题材、不同长度。别全拿同一个人的稿子标。
- 「说不准」的样本也存，但训练时会被跳过——留着以后判断。
- 打标不占每日免费次数。
- 同一条文本只会存一次（按 SHA1 去重），重复提交返回 `duplicate: true`。

### 第二步：训练

```bash
node calibrate.js            # 训练 + 评估 + 写入 calibration.json
node calibrate.js --dry      # 只看结果，不写文件
node calibrate.js --min 20   # 每类至少 20 条才训练
node calibrate.js --cv 5     # 5 折交叉验证
```

它干的事：

1. 对每个特征，分别算人类样本均值 `mh` 和 AI 样本均值 `ma`；
2. 用 **Cohen's d**（均值差 ÷ 合并标准差）衡量这项特征到底有多能区分；
3. `d < 0.25` 的特征判定为噪声，**直接关掉**——不让它继续制造误判；
4. `d` 越大权重越高（0.3～2.5 倍），最后归一化，保证总分尺度不变；
5. 锚点往对方方向让 20% 标准差，给「人机混写」留缓冲带；
6. 输出**留出集**（20% 没参与训练的样本）上校准前后的准确率对比。

输出长这样：

```
  留出集（24 条，未参与训练）：
    校准前  准确率 75%   AUC 0.812   平均分 AI 63.2 / 人 28.7
    校准后  准确率 87.5% AUC 0.906   平均分 AI 71.4 / 人 19.2
    提升    12.5 个百分点（最优阈值 52，准确率 91.7%）

  区分度最强的前 8 项：
    1. 叠词副词密度   d=2.31  w=1.84
    2. 眼神表情模板   d=2.05  w=1.63
    ...
  被关闭的噪声特征（6 项）：括号插话密度、词长分布…
```

**对外报数字请报交叉验证的结果（`--cv 5`），不要报全量自评**——那是自己考自己。

### 第三步：生效与回滚

- 训练完不需要重启，服务端每 15 秒检查 `calibration.json` 的修改时间；
- 旧参数自动备份成 `calibration.baseline.json`；
- 想回滚：删掉 `calibration.json`（或把 baseline 改回原名），下次检查就恢复默认锚点；
- 每次训练的 `createdAt` 和样本数都会写进文件，`/api/v1/stats` 能查到。

### 它学的是什么、不是什么

**是**：每个特征「人类大概多少、AI 大概多少、该有多敏感」。仍然是一张能读、能改、能审计的表。

**不是**：记住具体句子。所以它不会变成黑箱，也不会因为背过某篇稿子而给那篇打高分。换题材、换作者，得重新标一批。

**什么时候该重新训练**：换了主要客户群、换了题材（比如从都市转古风）、或者发现某一类文本老是被误判。重新标 30 条混合样本跑一次就行，很快。

### 第二步：训练自己的模型（数据到 100 条以上再做）

校准只调锚点，不改变"能看什么"。想让打分本身变聪明，用 `train.py`：

```bash
python train.py              # 训练 + 5 折交叉验证 + 写 model.json
python train.py --demo       # 用合成数据验证代码能跑通（不需要任何样本）
python train.py --cv 10      # 10 折交叉验证
python train.py --l2 0.01    # 调正则强度
```

它读 `samples.jsonl`，把 57 维特征标准化后训练一个逻辑回归：

```
z = b + Σ w_i · (v_i − mean_i) / std_i
p = sigmoid(z)
分数 = p × 100        （再套 40 / 70 两条线定档）
```

产出 `model.json`，服务端 15 秒内自动热加载，之后打分就走模型，界面元信息里会多一枚「**模型打分**」的标签。

特点：

- **纯 numpy**，不需要 GPU，不需要 sklearn，也不用装 transformers
- 57 个权重是学出来的，但**仍然能一行行看**（正数=越像 AI，负数=越像人写）
- 缺特征自动用中位数补，不会因为某个特征没算出来就崩
- 想回滚：删掉 `model.json`，立刻退回人工权重
- 样本门槛：每类 10 条能跑，100 条有意义，500 条以上才明显优于人工权重

训练的完整流程：

```bash
# 1. 先去网页上标样本（至少每类 10 条）
# 2. 验证代码正常
python train.py --demo

# 3. 用真数据训练
python train.py

# 4. 重启服务（模型也会热加载，但重启更稳）
node server.js
```

打印出来大概是这样：

```
  玄武 · 训练（逻辑回归）
  ----------------------------------------------------
  样本：AI 143 条，人类 156 条
  特征维度：57
  5 折交叉验证：准确率 88.3%　AUC 0.941
  全量自评：准确率 91.2%（阈值 0.48）　AUC 0.968

  权重最大的 10 项（正数=越像 AI，负数=越像人写）：
    lex_redup              w=+1.842
    syn_gaze               w=+1.517
    p_slang                w=-1.203
    ...
```

**对外报数字请用 `cvAccuracy`（交叉验证），不要用 `trainAccuracy`（自己考自己）。**

> **什么时候该上 BERT？**
> 当 `cvAccuracy` 卡在 0.88 左右上不去、且标注过 5000 条时。
> 那时候才值得动 GPU —— 一张 4GB 的 GTX 1650 就够微调 BERT-base（batch 4 + 梯度累积，约 2 小时）。
> 再往上要 1 万条标注，能到 90–92%，接近朱雀。

## 十一、已知误判场景（务必读）

1. **翻译腔、严肃文学、散文**：用词规整、标点克制、少口语，容易被判高。建议把「标点口语」权重降到 0.5，或调低 `p_slang` / `p_modal` 的 `h`。
2. **公文体、说明文、剧本旁白**：本来就该句句等长，检测失去意义。
3. **诗歌、意识流**：句长和标点本身就是形式，指标会失效。
4. **1500 字以下**：统计特征不稳，务必看置信区间。
5. **AI 生成后人工精修**：分数通常落在 40–59。这不是 bug，这就是事实——它确实是混写的。
6. **作者本人写作风格极其规整**：会有系统性偏高。这时候用「对照」功能，拿他自己的其他作品当基线，比绝对值可靠。

## 十二、如果拿去卖（合规与话术）

**能做：**
- 平台投稿初筛：把 60 分以上的稿件挑出来人工复核，效率提升 10 倍以上；
- 工作室过稿自检：改稿前跑一遍，改完再跑一遍，看分数有没有降；
- 编辑辅助：热力图直接告诉编辑「哪几句要改」；
- 私有化交付：内网部署，稿件不出机房，这是最好卖的点。

**不能做、也别声称能做：**
- 「鉴定某作品是 AI 生成」并作为处罚/诉讼依据 —— 任何纯统计方法都撑不住。
- 「判定准确率 99%」—— 不存在的。
- 处理合同中「AI 生成率超过 X% 即视为违约」这类条款 —— 只能作为参考证据之一，不能作为唯一依据。

**推荐话术：**

> 本工具给出的是**文本的机器书写倾向指标**及其对应的**可核查证据**，用于辅助人工判断与改稿，不构成对作品来源的最终认定。
> 报告中的每一条结论都可以定位到原文具体字句，供作者申诉与复核。

| 形态 | 定价锚点 |
|---|---|
